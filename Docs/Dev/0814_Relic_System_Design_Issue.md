# [Feature] 유물 시스템 및 대규모 피해량 기반

## 개요

런 전체에 영향을 주는 **유물 시스템**을 추가한다. 플레이어는 최대 8개의 유물을 조합하며, 유물은 탄환 구성·발사 순서·이동·재장전·치명타·상태 이상·탄환 파괴·초과 피해 사이에 새로운 시너지를 만든다.

유물은 다음 두 수명 유형을 지원한다.

- **런 지속형**: 획득 후 게임이 끝날 때까지 활성화된다.
- **소모·파괴형**: 특정 조건에서 한 번 또는 정해진 횟수만 발동하고 파괴된다. 예: 죽음에 이르는 피해를 1회 막고 파괴.

시너지가 완성된 빌드가 수억·조 단위 피해를 기록할 수 있도록 전투 수치도 함께 개편한다. 피해·체력·보호막 등은 `long`, 배율과 비율은 `double`을 사용하고 실제 전투와 피해 미리보기는 같은 계산기를 사용한다.

### 현재 기반 구현

> 2026-08-22 현재 공용 유물 19종을 활성화했다. 확률형 효과는 실제 행동에서만
> RNG를 소비하고 피해·사거리 미리보기는 결정적인 효과만 계산한다. 폭풍의 눈은
> 한 실린더에서 모든 적에게 피해를 주면 최고 단일 피해의 40%를 생존 적 전체에
> 적용하는 기존 규칙을 유지한다.

- `RelicData`, `RelicInstance`, `RelicManager`와 최대 8칸 보유·교체 API
- 런 지속형 및 충전 횟수를 사용하는 소모·파괴형
- 유물 ID, 스택, 충전 횟수, 이동 스택과 저장 피해의 런 저장·복원
- 일반 이동과 위치 교환 탄환의 실제 타일 거리 이벤트
- 이동 스택 기반 최종 피해 배율과 사격 단위 소비
- 첫 사격·마지막 사격 조건부 최종 배율
- 획득 가능한 모든 유물의 균등 무작위 보상 선택
- 직접 피해와 상태 피해에 공통으로 적용되는 죽음 방지
- 효과별 능력과 필요한 변수만 표시하는 전용 Inspector
- 초기 유물 4종

### 2026-08-22 공용 유물 규칙

- 최고급 조준경: 모든 탄환 사거리 +1
- 초탄 조준경 / 최후의 탄피: 조건부 최종 피해 ×1.3
- 행운의 약실: 정확히 6발 장전 시 무작위 약실 1개 최종 피해 ×2
- 포식자의 홀스터: 처치 후 다음 장전 탄환 1발 최종 피해 ×1.12. 효과가
  대기 중이거나 적용 대상 탄환이 남아 있으면 연속 처치로 횟수를 누적하지 않는다.
- 폐쇄 회로: 직접 피해를 받은 적 뒤의 가장 가까운 적에게 20% 피해 전이
- 감염성 배양기: 디버프 보유 대상 최종 피해 ×1.05
- 빈 박자 / 질주의 박차: 각각 재장전 30%, 이동 20% 확률로 턴 미소모
- 마차: 발차기 충돌 피해 ×1.5
- 사금 선별기: 적 처치 골드를 5% 확률로 7배
- 금이 간 뇌관: 물리 탄환당 10% 확률로 1회 추가 발사
- 저울: 생존 적 수를 `n`이라 할 때 최종 피해 +`max(0, 15-3n)%`
- 가문의 유언장: 보스 처치마다 모든 탄환 최종 피해 +5%
- 처형자의 서약: 처치 후 다음 탄환 최종 피해 ×1.15, 연속 처치 시 유지
- 변이 촉매: 디버프 대상 명중 시 40% 확률로 무작위 디버프 1스택 추가
- 벼랑 끝의 방아쇠: 체력 25% 이하에서 모든 탄환 최종 피해 ×1.2

HUD의 `Text | Stack`은 실제로 저장되는 중첩 수치만 표시한다. 중복 획득 스택과
이동 스택처럼 누적되는 상태는 표시하지만, 포식자의 홀스터·처형자의 서약 같은
1회 대기 상태와 금이 간 뇌관·빈 박자·질주의 박차 등의 발동 확률은 숫자로
표시하지 않는다.

이벤트·보물상자·보스 보상 화면, 전용 HUD와 전체 `long` 수치 마이그레이션은 후속 구현 범위다.

## 도입 목적

- 탄환 하나의 강화가 아닌, 여러 탄환과 행동을 연결하는 상위 성장 축을 제공한다.
- 시너지에 성공한 빌드가 수억·조 단위까지 폭발하도록 피해 상한을 확장한다.
- 노드를 진행할 때마다 빌드가 강해지고 있음을 크게 체감하게 한다.
- 유물 획득으로 기존 탄환의 가치와 최적 발사 순서가 바뀌는 발견의 즐거움을 만든다.
- 선택의 기대감, 시너지 완성, 큰 피해 숫자와 기록 갱신에서 오는 강한 보상감을 제공한다.
- 유물 풀과 획득 순서에 따라 매 런 다른 빌드와 플레이 방식을 만든다.

유물 관련 이벤트는 낮은 확률로 등장한다. 보물상자 씬과 보스 처치 보상에서는 유물을 확정적으로 획득한다. 유물은 상점에서 판매하지 않는다.

## 설계 원칙

- **탄환**은 실린더에서 무엇을 어떤 순서로 발사할지 결정한다.
- **유물**은 탄환과 행동을 평가하는 전역 규칙을 바꾼다.
- **아이템**은 제한된 횟수로 즉시 문제를 해결한다.
- 유물은 단순한 `모든 피해 +20%`보다 조건, 대가, 변환, 누적 또는 연쇄 작용을 제공한다.
- 큰 숫자는 기본 수치 인플레이션이 아니라 서로 다른 합연산·곱연산·추가 발동의 조합으로 만든다.
- 툴팁에서 `피해 +50%`와 `최종 피해 ×1.5`를 명확히 구분한다.
- 조건 충족과 발동은 아이콘 점등, 스택 표시, 피해 상세 정보로 확인할 수 있어야 한다.

## 보유 및 수명 규칙

- 동시에 활성화할 수 있는 유물은 최대 8개다.
- 8칸이 가득 찬 상태에서 새 유물을 얻으면 기존 유물과 교체하거나 획득을 포기할 수 있다.
- 중복 및 최대 스택 여부는 유물별로 설정한다.
- 런 지속형 유물은 교체·특수 효과로 제거되지 않는 한 게임 종료까지 유지된다.
- 소모·파괴형 유물은 남은 발동 횟수를 표시하고, 마지막 횟수 사용 직후 파괴되어 슬롯이 비워진다.
- 영구 스택이나 저장 피해를 가진 유물을 제거하면 해당 런타임 상태도 함께 제거한다.
- 유물의 고유 ID, 획득 순서, 스택, 충전 횟수와 런타임 상태를 저장한다.

유물마다 희귀도, 개별 등장 확률 또는 가중치를 두지 않는다. 보상 시점에는 현재 획득 가능한 모든 유물 중 하나 이상을 중복 없이 균등 무작위로 제시한다. 이미 보유한 중복 불가 유물과 최대 스택에 도달한 유물만 후보에서 제외한다.

## 유물 데이터

정적 정보는 `ScriptableObject`, 변하는 값은 별도의 런타임 인스턴스로 관리한다.

```text
RelicData
- Id, DisplayName, Description, Icon
- LifetimeType: RunPersistent / Consumable
- InitialCharges
- CanStack, MaxStack
- EffectType 또는 Effect 목록
- 발동 조건과 밸런스 수치

RelicInstance
- RelicData 참조
- StackCount, RemainingCharges
- PermanentCounter, StoredDamage, MovementStacks
- 턴/실린더/전투 한정 상태
- 획득 순서
```

정적 에셋을 런타임에 직접 변경하지 않는다. 저장 데이터에는 에셋 참조 대신 고유 ID와 필요한 상태만 기록한다.

## 전투 이벤트와 발동 규칙

유물이 각 전투 코드에 직접 의존하지 않도록 공통 이벤트 계층을 제공한다.

```text
BattleStarted / BattleEnded
TurnStarted
PlayerActionCompleted
PlayerMoved
ReloadStarted / ReloadCompleted
CylinderFireStarted / CylinderFireCompleted
BeforeShot
BeforeDamageCalculated / AfterDamageApplied
LethalDamageIncoming
CriticalTriggered
StatusEffectApplied
BulletDestroyed
EnemyDefeated
```

이벤트 문맥에는 공격 주체·대상, 탄환과 태그, 피해 출처, 이동 출처, 이동 타일 수, 기본 피해, 치명타, 일반 보너스, 최종 배율, 계산/적용/초과 피해, 실린더 상태, 연쇄 깊이, 실제 전투/미리보기 여부 등을 포함한다.

### 이동 집계

이동 기반 유물은 입력 방식이 아니라 **플레이어의 실제 타일 위치 변화**를 기준으로 한다.

- 일반 이동으로 이동한 타일 수를 집계한다.
- 위치 변경·위치 교환 탄환으로 이동한 거리도 집계한다.
- 순간 이동이나 교환은 시작 타일과 도착 타일 사이의 타일 거리만큼 집계한다.
- 이동에 실패했거나 같은 타일에 남으면 집계하지 않는다.
- 씬 초기화, 저장 복원, 전투 시작 배치는 이동으로 집계하지 않는다.
- 이동 원인을 `NormalMove`, `BulletEffect`, `Swap`, `ForcedMove` 등의 태그로 제공해 유물별 포함 범위를 설정할 수 있게 한다.
- 여러 칸 이동은 한 번의 이벤트와 `Distance` 값으로 전달해 타일마다 불필요한 중복 연출을 만들지 않는다.

예를 들어 이동 누적 유물은 전투 중 이동한 타일마다 스택을 얻고, 스택마다 다음 사격의 최종 피해를 곱하거나 더할 수 있다. 스택을 발사 시 소비할지, 실린더 종료 또는 전투 종료에 초기화할지는 유물 데이터로 정한다.

### 안정성

- 발동 순서는 시스템 우선순위 → 유물 획득 순서로 고정한다.
- 이벤트 도중 유물이 파괴돼도 현재 이벤트는 시작 시점 스냅샷을 기준으로 마친다.
- 소모형 유물은 효과 적용이 성공한 뒤 충전 횟수를 차감하고, 0이 되면 파괴한다.
- 유물이 만든 추가 피해와 추가 발사는 출처 태그를 가진다.
- 별도 허용이 없는 유물은 자신이 만든 이벤트로 자신을 재발동하지 않는다.
- 연쇄 깊이 또는 행동당 발동 예산으로 무한 재귀를 방지한다.
- 미리보기는 유물 스택, 충전 횟수, RNG, 통계와 저장 상태를 실제로 변경하지 않는다.

### 죽음 방지 유물

`LethalDamageIncoming`은 플레이어 체력이 실제로 0이 되기 직전에 발생한다.

- 유효한 죽음 방지 유물이 있으면 해당 피해를 무효화하거나 체력을 지정 값으로 남긴다.
- 효과가 성공한 뒤 충전 횟수를 1회 차감하고, 남은 횟수가 0이면 유물을 파괴한다.
- 동일 피해에 여러 죽음 방지 유물이 동시에 소비되지 않도록 첫 성공 후 이벤트를 종료한다.
- 독, 폭발, 충돌 등 모든 치명적 피해 경로에서 동일하게 동작한다.
- 즉사처럼 죽음 방지를 무시하는 효과가 필요할 경우 명시적인 태그를 사용한다.
- 피해 미리보기에는 죽음 방지 여부를 표시하지만 유물을 소비하지 않는다.

## 피해 계산 모델

```text
(기본 피해 + 고정 피해)
× (1 + 일반 피해 보너스의 합)
× 치명타 배율
× 개별 최종 피해 배율들
× 대상이 받는 피해 배율
= 한 번의 계산 피해
```

추가 발사와 재발동은 단순히 횟수를 곱하지 않고 각각 별도의 명중으로 처리한다. 보호막, 처치, 상태 이상과 유물 발동이 명중마다 평가돼야 하기 때문이다.

피해 결과는 다음을 구분한다.

```text
CalculatedDamage: 모든 공격 보정이 끝난 계산 피해
AbsorbedDamage: 보호막이 흡수한 피해
HealthDamage: 실제 체력 감소량
AppliedDamage: AbsorbedDamage + HealthDamage
OverkillDamage: max(0, CalculatedDamage - 피해 직전 유효 내구도)
```

- 피해 팝업과 최고 한 발 피해: `CalculatedDamage`
- 흡혈과 체력 기반 효과: `HealthDamage`
- 전투 피드백: `AppliedDamage`
- 초과 피해 기록과 관련 유물: `OverkillDamage`

## 대규모 수치 개편

| 용도 | 타입 |
| --- | --- |
| 피해, 체력, 보호막, 회복, 저장 피해, 피해 통계 | `long` |
| 일반 피해 보너스, 최종 배율, 치명타 배율, 비율 | `double` |
| UI 게이지와 애니메이션의 0~1 정규화 값 | `float` |
| 개수, 인덱스, 턴, 스택 | `int` 유지 가능 |

직접 공격뿐 아니라 치명타·표식, 독, 충돌, 벽 피해 전이, 연쇄·탄피 사격, 관리형 추가 피해, 피해 예약, 미리보기, 실린더 피해, 통계와 저장 데이터까지 같은 기준을 적용한다.

피해 계산에서는 다음 패턴을 제거한다.

```text
Mathf.CeilToInt / Mathf.FloorToInt / Mathf.RoundToInt
(float)damage를 거치는 배율 계산
int.MaxValue를 피해 상한으로 사용하는 처리
```

공통 `DamageMath`는 `long` 포화 덧셈·뺄셈, `double` 곱셈과 올림·내림, 안전한 비율 계산을 제공한다. 음수, `NaN`, 무한대와 오버플로를 방어하고 범위 초과 값은 `long.MaxValue`로 포화한다.

`double`의 정밀도는 현재 목표인 수억·조 단위에 충분하다. 실제 콘텐츠가 `long` 범위에 접근할 때만 별도의 거대 수 체계를 검토한다.

### 저장 및 에셋 마이그레이션

- 기존 전투 `ScriptableObject`의 `int → long` 변경 시 값 보존을 검증하고 Editor 마이그레이션을 제공한다.
- 저장 스키마 버전을 갱신하고 기존 JSON 정수를 `long`으로 복원한다.
- 유물 정보가 없는 기존 세이브는 빈 유물 목록으로 정상화한다.
- Unity 직렬화가 타입 변경을 자동 보존한다고 가정하지 않고 실제 에셋을 검증한다.

## 공통 피해 계산기와 미리보기

```text
DamageContext → DamageResolver → DamageResult
```

- 실제 공격과 미리보기가 동일한 기본 피해, 치명타, 상태와 유물 보정 함수를 호출한다.
- 미리보기는 복제된 상태에서 계산하고 실제 유물 스택이나 충전 횟수를 바꾸지 않는다.
- 유물 효과는 별도의 확률 판정 없이 조건을 만족하면 항상 발동한다.
- 직접·간접 피해의 출처 태그를 유지해 실제 전투와 동일한 유물만 발동한다.
- `PlayerShoot`의 실제 사격과 미리보기에 유물 조건문을 중복 구현하지 않는다.

## 큰 숫자 표시

공통 `LargeNumberFormatter`를 피해, 체력, 보호막, 통계와 결과 UI에 사용한다.

- 1억 미만: 천 단위 구분 기호를 포함한 전체 숫자
- 1억 이상 1조 미만: `억`
- 1조 이상: `조`
- 단위 변환 후 정수부 1자리는 소수 최대 2자리, 2자리는 최대 1자리, 3자리 이상은 정수 표시
- 불필요한 소수점과 0 제거
- 반올림으로 단위 경계를 넘으면 더 큰 단위로 다시 포맷
- 상세 툴팁에서는 쉼표를 포함한 원본 값도 제공

| 원본 값 | 표시 |
| ---: | ---: |
| `12,345` | `12,345` |
| `100,000,000` | `1억` |
| `1,230,000,000` | `12.3억` |
| `1,240,000,000,000` | `1.24조` |

## UI/UX

- `Panel | Floating > Panel | Relics`는 `RelicManager.OwnedRelics`의 모든 유효한 보유 유물을 획득 순서대로 표시한다. 1~4번째는 `Layout | Upper`, 5~8번째는 `Layout | Lower`를 사용하며, 아이콘이 누락된 유물도 숨기지 않고 대체 슬롯을 표시한다.
- 보유 유물 아이콘을 호버한 채 우클릭으로 2초간 누르면 `RelicManager`를 통해 제거한다. 툴팁은 이 조작을 안내하고 아이콘 상단의 Filled Image가 홀드 진행도를 표시한다.
- 전투 HUD에 최대 8개의 유물 아이콘을 표시한다.
- 툴팁에 효과, 수명 유형, 스택, 남은 충전 횟수, 저장 피해와 조건 진행도를 표시한다.
- 발동 시 아이콘이 반응하고 소모형 유물이 파괴되면 명확한 피드백을 제공한다.
- 8칸 상태의 획득 화면은 교체 또는 포기를 지원하고 제거될 상태를 경고한다.
- 큰 피해 연출 강도는 절대 숫자가 아니라 대상 최대 체력 대비 적용 피해 비율로 제한한다.

## 1차 빌드 확장안

다음 이름과 수치는 확정 데이터가 아닌 검토용 가안이다. 유물은 기존 탄환의 규칙을 연결하고, 신규 탄환은 각 빌드에 `생성 → 변환 → 폭발`의 순환을 만들어야 한다.

| 빌드 | 규칙 변화형 유물 후보 | 함께 추가할 탄환 후보 |
| --- | --- | --- |
| 포식자 | **사냥꾼의 송곳니**: 표식이 남은 적이 죽으면 모든 포식탄이 포식 1을 얻고, 남은 표식 절반을 가장 가까운 생존 적에게 이전한다. 한 적당 1회만 발동한다. | **도축탄**: 표식을 전부 소비해 소비량만큼 감쇠 추가타를 가한다.<br>**피 냄새탄**: 포식 스택이 있는 탄환이 적중한 대상에게 포식량에 비례한 표식을 부여한다. |
| 충전·축전 | **과전류 변압기**: 연쇄탄·탄피 수집 등으로 추가 사격이 발생할 때마다 장전 중인 충전·축전탄에 전력 1을 공급한다. 유물이 만든 추가 사격은 다시 공급하지 않는다. | **방전탄**: 장전 탄환들의 충전·전력·탄피를 정해진 양만큼 소비하고 자원 구간마다 추가타를 만든다.<br>**접속탄**: 자신의 충전·전력·탄피를 다음 탄환으로 이전한 뒤 파괴된다. |
| 디버프 증폭 | **감염성 배양기**: 상태 이상이 있는 적이 죽으면 각 상태 스택의 절반을 가장 가까운 생존 적에게 이전한다. 이전으로 발생한 처치는 재전염되지 않는다. | **전염탄**: 대상의 상태 이상 일부를 다른 모든 적에게 복제한다.<br>**촉매탄**: 활성 상태 이상 종류마다 1스택을 소비하고 종류별 추가타를 발생시킨다. 독은 맹독처럼 잔여 피해를 즉시 정산한다. |
| 유령 | **심령 탄창**: 유령 탄환을 재장전해 턴을 소모하지 않았다면 바로 다음 일반 탄환의 재장전도 턴을 소모하지 않는다. 턴당 1회다. | **잔영탄**: 발사 후 다음 재장전 더미에 일회용 복제본을 남긴다. 복제본의 재장전·발사는 턴을 소모하지 않으며 유산을 만들지 않는다.<br>**빙의탄**: 유령 탄환 다음에 재장전되면 직전에 발사한 탄환의 첫 특수 효과를 이번 실린더 동안 복사한다. |
| 태풍 | **폭풍의 눈**: 모든 적 대상 사격으로 적을 처치하면 생존 적에게 50% 위력으로 한 번 재발동한다. 재발동은 다시 이 유물을 발동하지 않는다. | **폭풍전야탄**: 다음 모든 적 대상 사격을 감소된 위력으로 한 번 복제한다.<br>**낙뢰탄**: 주 대상 적중 후 상태 이상이 있는 모든 적에게 감쇠 피해를 전이한다. |
| 광부 | **휴대용 제련소**: 전투 중 획득한 골드만큼 별도 광석을 저장한다. 도금탄 발사 시 광석을 구간 단위로 소비해 추가 사격을 만들며 전투 종료 시 초기화한다. | **광맥탄**: 적에게 광맥을 부여한다. 광맥 대상이 피격될 때 광석이 쌓이고 처치 시 스택만큼 골드를 얻는다.<br>**투자탄**: 골드를 지불해 이번 실린더 마지막에 자신을 한 번 다시 장전한다. 실린더당 1회만 가능하다. |
| 이동 | **질주의 박차**를 핵심으로 유지한다. 후속 후보 **관성 회수기**는 밀치기로 적이 실제 이동한 타일도 별도 관성 스택으로 저장해 다음 사격에 사용한다. | **견인탄**: 대상과 플레이어를 서로 한 칸씩 끌어당기며 실제 이동한 거리만 집계한다.<br>**반동탄**: 명중 후 플레이어가 탄환 비행 거리만큼 반대 방향으로 이동한다. 이동 불가 칸에서는 멈춘다. |
| 유산 | **탄도 납골함**: 실린더에서 처음 자가 파괴된 탄환을 저장하고 다음 재장전 때 일회용 잔영으로 되돌린다. 잔영 파괴는 유산을 만들지 않고 다시 저장되지 않는다. | **장례탄**: 다음 장전 탄환을 영구 파괴하고 그 탄환의 잔영을 즉시 두 번 발사한다.<br>**계승탄**: 다른 탄환이 파괴되면 그 탄환의 첫 특수 효과를 전투 종료까지 복사하며, 새 파괴가 발생하면 교체한다. |
| 하이롤러 | **붉은 차용증**: 탄환 효과로 잃은 체력을 혈액 부채로 저장한다. 다음 직접 공격이 최대 체력 10% 상당의 부채마다 추가타를 만들고 부채를 모두 소비한다. | **담보탄**: 발사 전에 최대 체력의 일정 비율을 잃고 강한 다단 공격을 가한다. 비용은 치명적일 수 있어 마지막 기회와도 연결된다.<br>**마진콜탄**: 체력을 1만 남기고 지불한 체력 구간마다 추가 사격한다. 이후 거머리·흡혈로 회복하는 극단적 마무리 탄환이다. |

### 공통 판정 원칙

- 유물 효과에는 별도의 발동 확률을 두지 않고 조건을 만족하면 확정 발동한다.
- 추가 사격, 전염, 잔영은 출처 태그와 재발동 금지 플래그를 가져 무한 연쇄를 막는다.
- 임시 잔영 파괴는 유산, 골드, 탄환 영구 파괴 통계를 발동하지 않는다.
- 체력 비용은 `비용 지불 → 죽음 방지 판정 → 공격 → 흡혈` 순서로 처리한다. 마지막 기회 사용 후에도 공격은 계속된다.
- 자원 이전과 소비 결과는 발사 미리보기와 탄환 툴팁에 함께 표시한다.

## 완료 조건

### 수치

- [ ] 단일 및 누적 피해가 `int.MaxValue`를 넘어도 잘리거나 음수가 되지 않는다.
- [ ] `1,230,000,000`은 `12.3억`, `1,240,000,000,000`은 `1.24조`로 표시된다.
- [ ] 조 단위 값이 피해, 체력, 보호막, 미리보기, 결과, 통계와 저장/불러오기에서 유지된다.
- [ ] 피해 계산에 `Mathf.CeilToInt`, `Mathf.FloorToInt`, `Mathf.RoundToInt`가 남지 않는다.
- [ ] 실제 공격과 확정 피해 미리보기가 같은 결과를 반환한다.
- [ ] 큰 수치에서도 체력 비율과 연출 값이 `NaN` 또는 무한대가 되지 않는다.

### 유물

- [ ] 유물을 최대 8개까지 보유하고 아홉 번째 유물을 교체하거나 포기할 수 있다.
- [ ] 런 지속형 유물이 게임 종료까지 유지된다.
- [ ] 죽음 방지 유물이 모든 일반 피해 경로에서 한 번만 발동하고 성공 후 파괴된다.
- [ ] 파괴된 유물의 슬롯과 런타임 상태가 정리되고 저장에도 반영된다.
- [ ] 일반 이동과 위치 변경 탄환의 이동 거리가 같은 규칙으로 누적된다.
- [ ] 이동 실패, 씬 배치와 저장 복원은 이동 스택을 만들지 않는다.
- [ ] 유물 ID, 스택, 충전 횟수와 저장 값이 이어하기 후 복원된다.
- [ ] 추가 피해·추가 발사 유물이 무한 재발동하지 않는다.
- [ ] 동일한 시드와 입력에서 발동 순서와 결과가 재현된다.

## 주요 검증 시나리오

1. 21억 초과 단일 피해와 1조 초과 실린더 피해를 실제 전투, 미리보기, UI, 통계와 저장에서 비교한다.

7. 죽음 방지 유물이 여러 개일 때 한 피해에 하나만 소비되는지 확인한다.
8. 소모형 유물 파괴 후 빈 슬롯, HUD와 저장 데이터가 즉시 일치하는지 확인한다.
9. 추가 사격 유물들이 서로 반응해도 발동 순서가 일정하고 무한 재귀가 없는지 확인한다.
10. WebGL에서 조 단위 계산, JSON 저장, TMP 표시와 유물 발동을 확인한다.

## 제외 및 추후 결정

이번 기반 구현에는 `long`을 넘는 거대 수 체계, 전체 유물 콘텐츠, 도감·메타 해금, 온라인 순위표와 다국어 숫자 단위를 포함하지 않는다.

다음 항목은 초기 구현 후 결정한다.

- 이벤트 등장 확률과 보상 선택지 수
- 중복 및 강화 방식
- 유물 교체·파괴·재련 기능
- 강제 이동을 이동 기반 유물에 포함할 기본 정책
- 이동 스택의 소비·초기화 시점과 배율 상한
- 죽음 방지 후 남길 체력과 무적 시간
- 행동당 연쇄 발동 예산
