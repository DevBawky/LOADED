# 실린더 탄환 호버 피해 예측

## 기본 정보

- 작성일: 2026-08-03
- 관련 기능: 실린더 UI / 탄환 툴팁 / 전투 피해 계산 / 적 체력바
- 주요 목적: 장전된 탄환을 호버했을 때 해당 탄환까지의 확정 피해를 적의 `HP_Value`에 누적 표시

## 요구사항

- 실린더에 장전된 탄환을 호버하면 기존 탄환 툴팁과 함께 예상 피해를 표시한다.
- 호버한 탄환이 실제 발사될 때 피격될 적을 대상으로 한다.
- 확정 관통이 있는 경우 관통으로 맞게 될 모든 적에게 표시한다.
- 확률 효과는 포함하지 않고 확정되는 피해만 표시한다.
- 실드 시스템은 고려하지 않는다.
- 피해량 숫자는 표시하지 않는다.
- 각 피해 구간은 해당 실린더 탄환의 `PrimaryLineColor`를 사용한다.
- 세 번째 탄환을 호버하면 첫 번째와 두 번째 탄환의 선행 피해도 함께 누적하고, 세 번째 탄환의 피해를 강조한다.
- 예상 피해는 `HP_Bar`가 아니라 실제 체력 게이지인 `HP_Value`를 기준으로 표시한다.
- 기존 적 체력바 셰이더를 확장해서 사용한다.

## 사용자 흐름

1. `InventoryTooltipUI`가 마우스 아래에 있는 실린더 탄환과 장전 순번을 찾는다.
2. 기존 Bullet Tooltip을 표시한다.
3. `PlayerShoot.ShowLoadedBulletDamagePreview(index)`를 호출한다.
4. `PlayerShoot`이 첫 번째 탄환부터 호버한 탄환까지 발사 결과를 순서대로 시뮬레이션한다.
5. 피격 대상별로 남은 체력과 탄환별 피해 구간을 누적한다.
6. 각 `EnemyController`가 구간 목록을 `EnemyHealthBarFeedback`에 전달한다.
7. `EnemyHealthBarFeedback`이 `HP_Value` 자식으로 예상 피해 오버레이를 만들고 셰이더에 구간과 색상을 전달한다.
8. 호버가 끝나거나 UI 상태가 바뀌면 모든 적의 예상 피해를 제거한다.

## 피해 예측 규칙

### 발사 순서

호버한 탄환만 단독으로 계산하지 않는다. 장전 순서의 첫 탄환부터 호버한 탄환까지 순차적으로 계산한다.

예를 들어 세 번째 탄환을 호버한 경우 다음 순서를 사용한다.

```text
현재 적 체력
  → 1번 탄환 확정 피해
  → 2번 탄환 확정 피해 및 확정 상태 변화
  → 3번 탄환 확정 피해
```

따라서 앞 탄환이 적을 처치하거나 표식 같은 확정 상태를 적용하면 뒤 탄환의 대상과 피해도 그 결과를 반영한다.

### 포함하는 결과

- 기본 공격 피해
- 100% 확정 치명타
- 100% 확정 관통
- 확정 연쇄 발사와 추가 사격
- 확정 탄환 효과 및 조건부 효과
- 표식 등 선행 탄환이 확정적으로 만든 상태에 따른 후속 피해 변화
- 위치, 사거리, 넉백 충돌 등 현재 전투 로직에서 확정적으로 판정 가능한 결과

### 제외하는 결과

- 100% 미만 확률의 치명타
- 100% 미만 확률의 관통
- 100% 미만 확률로 발동하는 탄환 효과
- 무작위 결과를 전제로 하는 피해
- 피해량 숫자 UI
- 실드 계산

## 피격 대상 선택

`PlayerShoot.BuildGuaranteedPreviewHitTargets`가 현재 보드 상태와 발사 방향을 기준으로 확정 피격 대상을 구성한다.

- 일반 탄환은 첫 번째 유효 적을 대상으로 한다.
- 확정 관통 단계가 있으면 다음 적도 순서대로 포함한다.
- 확률 관통은 해당 단계 이후의 적을 포함하지 않는다.
- 선행 탄환으로 적이 사망했다면 후속 탄환은 갱신된 가상 전투 상태를 기준으로 다음 대상을 찾는다.

## 피해 구간 데이터

적마다 `DamagePreviewEnemyState`를 유지한다.

- 현재 시뮬레이션상 남은 체력
- 보드 타일 위치
- 확정 상태 이상 스택
- 탄환별 `DamagePreviewSegment` 목록

각 `DamagePreviewSegment`는 다음 값을 가진다.

| 값 | 설명 |
| --- | --- |
| `Damage` | 실제 남은 체력에 적용 가능한 예상 피해 |
| `Color` | 발사될 실린더 탄환의 `PrimaryLineColor` |
| `Emphasized` | 현재 호버 중인 탄환의 피해인지 여부 |

연속된 구간의 색상과 강조 상태가 같으면 하나의 구간으로 병합한다. 이 처리로 같은 탄환에서 발생한 연속 피해 사이에 빈 줄이나 겹침이 생기는 것을 방지한다.

## 체력바 표시 구조

예상 피해 오버레이는 런타임에 다음 계층으로 생성한다.

```text
HP_Bar
└─ HP_Value
   ├─ HP_DamagePreview_1
   └─ Text | HP
```

`HP_DamagePreview_1`은 `HP_Value`의 자식이며 다음 레이아웃을 사용한다.
예상 피해 오버레이는 항상 첫 번째 자식으로 유지해 체력 수치 `Text | HP`보다 먼저 렌더링한다.

- `anchorMin = (0, 0)`
- `anchorMax = (1, 1)`
- `anchoredPosition = (0, 0)`
- `sizeDelta = (0, 0)`
- `localScale = (1, 1, 1)`

따라서 피해 비율 `0.94~1.0`은 `HP_Bar`가 아닌 `HP_Value` 실제 너비의 오른쪽 6%에 대응한다.

오버레이 Image는 원본 체력 스프라이트의 둥근 투명 테두리를 재사용하지 않는 단순 사각형으로 만든다. 예상 피해 셰이더는 이 오버레이의 0~1 UV를 체력 비율 좌표로 사용한다.

## 셰이더 처리

기존 `EnemyHealthBarImpact.shader`에 Preview Mode를 추가했다.

- 하나의 전체 너비 오버레이 Image에서 최대 8개 피해 구간을 처리한다.
- `_PreviewRange0`부터 `_PreviewRange7`까지 구간 시작점, 끝점, 강조 여부를 전달한다.
- `_PreviewColor0`부터 `_PreviewColor7`까지 탄환별 Primary Color를 전달한다.
- 각 픽셀이 어느 구간에 속하는지 `SelectPreviewSegment`에서 판정한다.
- 작은 seam padding을 적용해 인접 구간 사이의 빈 줄을 방지한다.
- 호버한 탄환 구간에는 더 빠른 스트라이프와 강한 밝기 변화를 적용한다.

탄환 궤적은 발광 방식으로 렌더링되지만 체력바는 일반 알파 블렌딩을 사용한다. 매우 어두운 Primary Color가 검게 뭉개지지 않도록 색조는 유지하면서 최소 가시성만 보정한다.

## 발견된 문제와 수정 내역

### 탄환별 구간 사이가 끊겨 보임

초기 구현은 피해 구간마다 별도 Image를 생성했다. 각 Image의 채움 경계와 셰이더 가장자리 처리가 겹치면서 검은 줄 또는 빈 간격이 발생했다.

현재는 하나의 전체 너비 Image에서 모든 구간을 동시에 선택하도록 변경했다. 동일 색상·동일 강조 상태의 연속 피해도 사전에 병합한다.

### 첫 번째 탄환에서 검은 줄이 표시됨

첫 구간의 기준 체력이 이전 프리뷰 상태의 `Image.fillAmount`에 의존하면 도메인 리로드나 호버 전환 후 잘못된 위치가 남을 수 있었다.

현재는 프리뷰를 열 때마다 다음 값으로 기준점을 다시 만든다.

```csharp
(float)currentHealth / maxHealth
```

### Primary Color가 올바르지 않음

클론이나 다른 탄환 해석 효과가 적용될 때 해석된 탄환의 색상을 사용하면 실제 실린더에서 소비될 탄환과 색상이 달라질 수 있었다.

현재는 전투 동작을 대신 수행하는 탄환과 관계없이 실제 발사 슬롯의 `firedBullet.PrimaryLineColor`를 사용한다.

### 약한 첫 탄환이 풀 HP에서 보이지 않음

표식 탄환처럼 피해가 작은 탄환은 피해 구간이 `0.94~1.0`처럼 체력바 오른쪽 끝에 위치한다. 기존 오버레이는 `HP_Value`의 레이아웃을 복사했지만 실제 부모가 `HP_Bar`였고, 원본 둥근 UISprite의 오른쪽 투명 테두리까지 사용했다. 그 결과 작은 구간 전체가 투명 영역에 들어가 보이지 않을 수 있었다.

수정 내용은 다음과 같다.

- 오버레이의 실제 부모를 `HP_Value`로 변경
- `HP_Value` 전체 영역에 1:1 스트레치
- 원본 둥근 UISprite 대신 전용 사각형 오버레이 사용
- 셰이더에서 오버레이 자체의 0~1 UV를 사용
- 어두운 Primary Color의 최소 가시성 보정

### 스크립트 리컴파일 후 오버레이가 사라짐

도메인 리로드 과정에서 기존 동적 오버레이 GameObject는 삭제 예정이지만 내부 추적 리스트에는 참조가 남는 경우가 있었다. 이 상태에서는 새 오브젝트를 생성하지 않고 곧 삭제될 참조를 다시 사용할 수 있었다.

정리 과정에서 기존 `HP_Bar` 자식과 새로운 `HP_Value` 자식을 모두 검사하고, 삭제 예정 오브젝트의 Image 및 Material 참조 목록을 비운 뒤 새 오버레이를 생성하도록 수정했다.

dotnet build Assembly-CSharp.csproj --no-restore

### Play Mode 확인 항목

- 풀 HP 적에게 피해 6인 표식 탄환을 첫 슬롯에 장전하고 호버했을 때 `HP_Value` 오른쪽 끝에 구간이 보이는지 확인한다.
- 일반 탄환 다음에 표식 탄환을 장전하고 두 번째 탄환을 호버했을 때 두 구간이 빈틈 없이 이어지는지 확인한다.
- 세 번째 탄환을 호버했을 때 첫 번째와 두 번째 피해가 누적되고 세 번째 구간만 강조되는지 확인한다.
- 확정 관통 탄환이 여러 적의 `HP_Value`에 각각 피해를 표시하는지 확인한다.
- 확률 관통 및 확률 치명타가 프리뷰에 포함되지 않는지 확인한다.
- 호버 종료, 드래그 시작, 일시정지 및 전투 상태 변경 시 오버레이가 제거되는지 확인한다.
- Play Mode 중 스크립트 리컴파일 이후 다시 호버했을 때 `HP_DamagePreview_1`이 재생성되는지 확인한다.

## 현재 상태

기능 구현과 컴파일 검증은 완료되었다. `HP_Value` 직접 자식 구조로 변경한 최종 렌더링 결과는 Unity Play Mode에서 실제 해상도와 카메라 배율을 기준으로 최종 육안 확인이 필요하다.
