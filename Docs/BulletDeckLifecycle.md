# 탄환 보유량·순환·소진 시스템 설계

## 배경

기존 시스템은 파괴 효과가 있는 탄환을 `OwnedBulletCount`에서 제외했다. 이 값이 최소 보유량 7개와 최대 보유량 15개 양쪽에 사용되면서, 실제 탄환이 15개여도 상점 구매 버튼이 활성화되는 문제가 발생했다.

논의 과정에서 파괴 탄환을 별도의 예외로 유지하기보다, 탄환 소진 자체를 플레이어가 감수할 수 있는 덱 구성 리스크로 취급하기로 결정했다. 이에 따라 모든 탄환은 동일하게 보유량에 포함하며, 전투 중 마지막 탄환이 파괴되면 패배한다.

## 최종 규칙

- 모든 탄환은 파괴 가능 여부와 관계없이 총 보유량에 포함한다.
- 최대 보유량은 20개다.
- 상점과 정비 화면에서는 최소 1개를 남겨야 한다.
- 전투 효과는 마지막 탄환도 파괴할 수 있다.
- 현재 발사 시퀀스와 연쇄 효과가 끝난 뒤 총 보유량이 0개라면 패배한다.
- 마지막 탄환으로 마지막 적을 처치했다면 전투 클리어를 우선한다.
- 업그레이드로 탄환의 파괴 가능 여부가 바뀌어도 보유량은 달라지지 않는다.

핵심 불변 조건은 다음과 같다.

```text
TotalBulletCount = deck.Count + loadedBullets.Count + graveyard.Count
0 <= TotalBulletCount <= 20

정비소에서 허용되는 최소 TotalBulletCount = 1
전투 효과로 도달 가능한 최소 TotalBulletCount = 0
```

## 다음 탄환 예약 방식

탄환 수가 실린더 용량 이하라면 모든 탄환이 실린더에 들어가 `deck`이 비게 된다. 기존 `PeekNextBullet()`은 `deck`만 조회했기 때문에 이때 다음 탄환을 표시하지 못했다.

이를 해결하기 위해 마지막 덱 탄환을 장전하는 순간 `NextCycleOrder`를 만든다. 이 목록은 실제 탄환 저장소가 아니라 다음 순환의 순서표다. 탄환 인스턴스는 여전히 `deck`, `loadedBullets`, `graveyard` 중 정확히 한 곳에만 존재한다.

```text
현재 실린더: A, B, C
다음 사이클 예약: B, C, A
다음 탄환 표시: B
```

파괴 확률은 미리 판정하지 않는다. 치명타, 관통, 적 처치처럼 실제 전투 결과에 의존하는 조건부 파괴가 존재하고, 사전 판정은 RNG 소비 시점과 전투 결과를 바꿀 수 있기 때문이다.

발사 중 탄환이 파괴되면 예약 목록에서도 해당 탄환을 제거한다. 발사 시퀀스가 끝나면 생존하여 묘지에 있는 탄환을 예약 순서대로 실제 덱에 배치한다. 예약 목록에 없던 탄환은 별도로 섞어서 뒤에 배치한다.

다음 탄환 조회 우선순위는 다음과 같다.

1. `deck`에 탄환이 있으면 덱의 최상단 탄환
2. `deck`이 비었으면 `NextCycleOrder`의 첫 생존 탄환
3. 둘 다 없으면 탄환 없음

## UI 갱신 원칙

발사 중에는 다음 탄환 UI를 고정한다. 탄환마다 `StateChanged`가 발생하더라도 아이콘을 즉시 교체하지 않고, 발사 시퀀스가 끝난 후 확정된 결과로 한 번만 갱신한다.

- 표시된 후보가 생존하면 아이콘을 유지한다.
- 표시된 후보가 파괴되면 다음 생존 후보로 한 번 전환한다.
- 표시되지 않은 후보가 파괴돼도 현재 아이콘은 바뀌지 않는다.
- 모든 탄환이 파괴되면 아이콘을 비우고 탄환 소진 패배로 전환한다.

다음 탄환 아이콘은 미래 순환 후보도 보여줄 수 있으므로, 현재 즉시 장전할 수 있는 탄환 수를 별도로 표시한다.

```text
장전 가능 탄환 수 = deck.Count + graveyard.Count
표시 형식 = 장전 가능: {장전 가능 탄환 수}
```

총 보유 탄환이 1개이고 실린더에 장전된 경우 다음 탄환에는 같은 탄환이 표시되지만 `장전 가능: 0`이 표시된다. 이는 탄환이 복제됐다는 의미가 아니라, 발사 후 생존했을 때의 다음 순환 후보를 보여주는 것이다.

## 상점 UI

- 상점 보유량은 `TotalBulletCount / 20`으로 표시한다.
- 총 20개일 때 파괴 탄환을 포함한 모든 탄환 구매를 차단한다.
- `Layout | Current Bullets` 아래 네 행을 사용한다.

```text
Layout | 1: 1~5
Layout | 2: 6~10
Layout | 3: 11~15
Layout | 4: 16~20
```

행 목록은 프리팹의 기존 직렬화 값에 의존하지 않고 현재 자식 행을 다시 탐색하므로, 추가된 `Layout | 4`도 자동으로 포함된다.

## 전투 종료 우선순위

탄환 소진은 `TryDestroyBullet()` 안에서 즉시 패배로 처리하지 않는다. 현재 발사와 조건부 효과가 모두 끝난 뒤 다음 순서로 처리한다.

1. 발사 및 연쇄 효과 처리
2. 적 사망과 전투 완료 확정
3. 다음 사이클 덱 확정
4. 총 보유 탄환 수 검사
5. 전투가 끝나지 않았고 탄환이 0개라면 게임 오버

이 순서를 통해 마지막 탄환이 자신을 파괴하면서 마지막 적도 처치한 경우 전투 클리어가 정상적으로 우선한다.

## 주요 검증 시나리오

- 파괴 탄환을 포함해 20개를 보유하면 구매할 수 없다.
- 수동 제거로는 마지막 1개를 없앨 수 없다.
- 탄환 1개만 장전하면 같은 탄환이 다음 사이클 후보로 표시되며 장전 가능 수는 0이다.
- 해당 탄환이 생존하면 발사 종료 후 다시 장전 가능 수가 1이 된다.
- 마지막 탄환이 파괴돼도 발사 효과 처리 중에는 패배하지 않고, 시퀀스 종료 후 패배한다.
- 다음 탄환 후보가 파괴되더라도 발사 도중 아이콘이 연속해서 바뀌지 않는다.
- 마지막 적과 마지막 탄환이 동시에 제거되면 전투 클리어가 우선한다.
- 상점 보유 탄환 20개가 네 번째 행까지 모두 표시된다.
